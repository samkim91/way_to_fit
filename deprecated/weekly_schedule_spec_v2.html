DB Schema 엔티티 설계
ScheduleTemplate — 시간표 버전 마스터
id UUID PK
box_id FK
effectiveStartDate Instant — Asia/Seoul 기준 당일 00:00을 UTC Instant로 변환하여 저장
generateMonths Int — 인스턴스 생성 개월 수 (편집 폼에서 입력)
status Enum(DRAFT, SCHEDULED, ACTIVE, ARCHIVED)
createdAt / updatedAt Instant
ClassRoutine — 버전에 속한 주간 수업 규칙
id UUID PK
template_id FK → ScheduleTemplate
dayOfWeek Enum(MONDAY…SUNDAY)
startTime / endTime Instant
capacity Int? — null = 무제한
ClassRoutineCoach — 수업 ↔ 코치 N:M
routine_id FK / coach_id FK — 복합 PK
ClassInstance — 실제 캘린더 수업
id UUID PK
routine_id FK → ClassRoutine
classDate Instant — 실제 수업 일시 UTC
isCancelled Boolean default false
createdAt Instant
ClassReservation — 회원 예약
id UUID PK
instance_id FK → ClassInstance
member_id FK
status Enum(CONFIRMED, CANCELLED)
createdAt Instant
* 인스턴스 폐기 시 CONFIRMED 예약 일괄 CANCELLED 처리 후 알림 발송
Backend REST API
시간표 버전 관리
POST /api/v1/schedule-templates — Template + Routines + CoachMappings 단일 트랜잭션 생성, status = DRAFT
GET /api/v1/schedule-templates — 버전 목록 (status 필터 가능)
GET /api/v1/schedule-templates/active?at={instant} — 특정 시점 기준 ACTIVE 버전 조회
PUT /api/v1/schedule-templates/{id} — DRAFT 상태일 때만 수정 가능
DELETE /api/v1/schedule-templates/{id} — DRAFT만 삭제 가능
배포 확정 updated
POST /api/v1/schedule-templates/{id}/deploy
effectiveStartDate가 오늘(Asia/Seoul)이면 → 즉시 ACTIVE 전환 + 인스턴스 Bulk Insert
effectiveStartDate가 미래이면 → SCHEDULED 전환, 스케줄러에 위임
두 경우 모두 기존 ACTIVE 템플릿의 미래 인스턴스 폐기 + 연결 예약 CANCELLED 처리 포함
인스턴스(캘린더) 관리
GET /api/v1/class-instances?from={instant}&to={instant} — 월간 캘린더 조회
PATCH /api/v1/class-instances/{id}/cancel — 휴강 토글
Business Logic Service Layer 규칙
Template 저장 시 검증
동일 box_id 내 effectiveStartDate 중복 불가 (DRAFT 제외)
effectiveStartDate는 현재 시점(Instant.now()) 이후여야 함
deploy() 공통 처리 흐름 updated
기존 ACTIVE 템플릿 → ARCHIVED
기존 ACTIVE 템플릿의 미래 ClassInstance 삭제 (cascade)
연결된 CONFIRMED ClassReservation → CANCELLED + 알림 발송
신규 템플릿 → ACTIVE + generateMonths개월치 ClassInstance Bulk Insert
* 즉시 적용(오늘)과 스케줄러 실행(미래) 모두 이 흐름을 공유하는 내부 함수로 추출
스케줄러 — 매일 00:00 Asia/Seoul 실행
오늘 날짜와 effectiveStartDate가 일치하는 SCHEDULED 템플릿 탐색
위 deploy() 공통 흐름 실행

Frontend LocalStorage 임시저장 전략
키 구조
기존 템플릿 편집: schedule-draft:{templateId}
신규 작성: schedule-draft:new
* 템플릿별로 키가 분리되어 동시에 여러 draft를 작성해도 데이터가 섞이지 않음
저장 시점
수업 추가/수정/삭제, effectiveStartDate/generateMonths 변경 시 debounce 1s 후 자동 저장
저장 데이터 구조: { templateId, savedAt: Instant, routines, meta }
페이지 진입 시 복원 로직
해당 키의 LocalStorage 데이터 존재 여부 확인
존재하면 Toast: "HH:mm에 임시저장된 내용이 있습니다. 불러올까요?" [불러오기] [무시]
[무시] 선택 시 해당 키 즉시 삭제 — 다음 진입 시 재표시 없음
서버 저장 성공 후 정리
deploy API 성공 응답 수신 시 해당 키(schedule-draft:{templateId} 또는 schedule-draft:new) 즉시 삭제
신규 작성 후 서버에서 templateId 발급되면 키를 new → {templateId}로 마이그레이션 후 삭제
* 저장 실패 시 LocalStorage 유지 — 재시도 가능
